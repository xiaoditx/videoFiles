计算机中有真随机吗？
{c}
很多人会告诉你
{big}没有
{c}
但今天我要告诉你
{big}有
{c}
它的实现，依赖于一个设备
真随机发生器（TRNG）
这个设备早已被安装到了大多数的现代PC/移动设备中
{c}
TRNG通过量化人类无法控制的物理现象来获取真随机数据
包括电子噪声、放射衰变、光子噪声、混沌系统等等
其原理偏向物理，我们不过多赘述
{c}
传统C/C++开发采用下面的代码获取随机数：
:const int seed = 1000;
:srand(seed);
:int rand_value = rand();
{c}
这个代码存在一个问题，就是固定种子
这导致，程序每次启动，获取的随机数序列是一致的
我们完全可以倒推种子预测下一个随机数
{c}
于是，程序员们选择采用不固定的种子进行初始化
最常见的做法就是：时间
还是取随机数
:srand(time(NULL));
:int rand_value = rand();
于是程序的随机值在每次启动时就有了区别
{c}
但这依旧不安全
C/C++的标准规定了rand可以取到0到RAND_MAX内的任意整数
但是没有规定随机算法，交由编译器实现决定
因此不能保证其安全
大多数的实现也确实不安全
多采用了线性同余生成器（LCG）
逆推极其简单
{c}
为此，C++引入了random头来实现更好的随机数获取质量
我们可以使用其中提供的“随机数设备”生成真随机
:std::random_device rd;
:auto rand_value = rd();
{c}
真随机设备依赖于TRNG，但有的旧设备或低端设备没有装配
因此random_device提供了退化策略
下面我们以MinGW的实现为例
讲讲退化策略
{c}
实现首先会尝试使用RDRAND/RDSEED硬件指令获取随机数
这是有TRNG的理想情况
当TRNG无法使用时候，实现会尝试使用windows的rand_s API
这个API是密码学安全的，通常比较可靠
当rand_s也失败时，实现最后退化到线性同余生成器
可以理解为srand(time(NULL))后用rand获取了一个随机数
这个流程起码在MinGW提供的g++ 15.2.0上成立，旧版可能有所不同
{c}
随机数设备虽然在大多数现代设备上都能取到真随机
但它依赖记录物理现象，速度较慢
下面两张截图展示了随机数设备与rand各取500000000次随机数的时间差异（Windows10,dev C++集成环境编译）
{展示图片a.png,b.png,如果无法直接展示则预留空位，尺寸约600x170}
可以看出差距非常大
{c}
因此，在一些安全性不是特别重要但又要防止随机算法被轻易倒退的领域，大多采用下面的方案：
先使用随机数设备获取真随机数字
再初始化高质量伪随机算法引擎从而获得随机的随机数
{c}
我们来看个例子：
std::random_device rd;
std::mt19937 gen(rd());
std::cout << gen();
这个例子中，使用真随机初始化了一个mt19937对象
这个对象就是使用了“梅森旋转算法”的算法引擎
这种算法质量、速度相对其他更优，但它不是密码学安全的
若想要根据需求选择其他算法，可自行查阅reference
需要注意的是，mt19937不是密码学安全
密码、令牌、会话ID等场景还是请直接使用操作系统提供的CSPRNG或者自行实现CSPRNG，如Linux的getrandom()、Windows的BCryptGenRandom
{c}
random不止提供了真随机和高质算法
它还提供了另一样东西：分布
C/C++中，随机数的区间是固定的
比如rand的区间是0到RAND_MAX闭区间
即使是random_device、mt19937都是固定区间取值
但我们有时只想取得一定区间的数值
比如1到6闭区间的任意整数
传统C/C++的做法是取随机后取余数
于是就写成
int a = (rand()%6)+1;
{c}
这导致了一个问题：即使随机数概率均匀，我们取余数的结果也是分布不均的
让我们假设RAND_MAX = 32767
那么 rand() 有 32768 个可能值
我们对其取10的余数
可以推出：
:32768 = 10 * 3276 + 8
:余数 0~7 各出现 3277 次
:余数 8~9 各出现 3276 次
因此每个余数的概率不完全相等
偏差很小，但确实存在
{c}
random提供的分布正好解决了这一问题
比较常用的一个，是整数分布std::uniform_int_distribution
我们可以采用这样的方式让取到的随机数均匀的分布到[1,6]内：
std::random_device rd;
std::mt19937 gen(rd());
std::uniform_int_distribution<int> dist(1,6); 
std::cout << dist(gen);
分布的通常实现是“拒绝采样”
也就是仍然是取模的算法但会先抛弃多余的部分
用上面[0,RAND_MAX]分布放到[0,9]的例子
就是直接舍弃最后8个数字
{c}
你可能会说：那这个功能也不是很厉害啊
错
std::uniform_int_distribution只是冰山一角
random还提供了大量其他分布
这里列出一些常用的
- 分布 | 参数 | 意义
- std::uniform_real_distribution | a,b | [a,b)范围内的实数
- std::bernoulli_distribution | p | 成功概率为p的伯努利分布
- std::binomial_distribution | n,p | 成功概率为p的n重伯努利实验的成功次数
- std::negative_binomial_distribution | k,p | 达到k次成功前的失败次数
- std::geometric_distribution | p | 第一次成功前的失败次数
- std::normal_distribution | a,b | 均值为a，标准差为b的正态分布
random提供了约20种分布，用法可自行查阅reference
{c}
现在，让我们来重写取随机数，先看传统写法
:srand(time(NULL));  // 初始化
:int a = (rand%6)+1  // 取随机并分布到[1,6]
我们来用random改写
std::random_device rd;  // 初始化随机数设备
std::mt19937 gen(rd());   // 初始化伪随机引擎
std::uniform_int_distribution<int> dist(1,6); // 初始化分布
int a = dist(gen);      // 取随机数
{c}
至此，我们取到了分布均匀、速度较快、较难预测的随机数
